# atomost-bench v1 — 结果（2026-10-27）

> 公开版（2026-10-29）：题目原文与小项目样本（含团队内部规矩）、记忆副本、冻结文件清单、每次运行的调用与记录、构建脚本和 atomost 代码不公开，尽调时可申请查看；文中的 `results/`、`items/`、`arms/`、`engine/` 都在私有部分。几处项目内部的计算设置写成了泛称。英文摘要见 `SUMMARY.en.md`。

问的问题：第二轮的做法（常驻索引砍短，规矩改由规则钩子在动作时送到、记忆改由注入在碰到时送到）是否达到 BASELINE §4b
的成功标准：常驻上下文明显变小、token 不升、守规矩不降。Haiku 与 Opus 各量；Fable 待 owner 定。

## 跑了什么

30 道做事题（三个试点各 10）× 三组 × 两个模型 × 3 次 = 540 次，2026-10-27 09:07–10:25。题目与答案键在任何正式运行前冻结
（`FREEZE.sha256`，577 个文件；跑后复核 0 改动）。三组：F 全量索引、无钩子；L 精简索引、无钩子；N 精简索引 + 规则 + 注入。
标价 $38.81（Haiku $1.51、Opus $37.30；取自 Claude Code 每次自报的 total_cost_usd，走订阅不另付），基准自己的注入服务 Haiku 把关 24 次 $0.008。0 次出错、0 次撞额度。

## 结论

| | Haiku F | Haiku N | Opus F | Opus N |
|---|---|---|---|---|
| 开头常驻上下文（中位，token） | 13,976 | 12,276（−12%） | 13,148 | 11,445（−13%） |
| 每次总 token（平均） | 112,236 | 115,233（+3%） | 87,161 | 85,212（−2%） |
| 每次美元（含把关） | 0.0054 | 0.0057 | 0.1415 | 0.1367 |
| 守规矩（最终状态，90 次） | 69 | 78 | 75 | 82 |
| 头一次就守 | 64 | 65 | 72 | 81 |
| 活干完 | 87 | 86 | 85 | 83 |

- **常驻变小**：是，约 1,700 token、12–13%。分项目：memory-control 只少约 300（它的索引本来就短），cophon 少约 2,500
  （−16%），deeph 少约 1,700（−12%）。整段开场上下文大头是系统提示和工具说明，索引砍得再狠也到不了砍半。
- **token 不升**：大体成立。Opus 降 2%；Haiku 升 3%，主要在 deeph（N 组平均多 15%，被规则拦下后要重来）。
- **守规矩不降**：成立，而且两个模型都升：Haiku 69→78、Opus 75→82。按题配对检验，N 比 F 好的可能偶然性 Haiku p≈0.09、
  Opus p≈0.31；比"只砍索引、不开钩子"的 L 组好得更清楚（p≈0.03、0.07）。即：只砍索引会掉（L 比 F 少 3–4 次），
  钩子把它补回来还多一点。
- **活干完**：N 少 1–2 次，在噪声内；差在 M05（两个模型各一次）和 C08（Opus 一次），没细查原因。

## 差别出在哪几题（每格 = 3 次里守了几次，F / L / N）

赢的：
- M03 改错日志要追加更正、不就地改（全机规则，全局 CLAUDE.md 里三组都常驻）：Haiku 0/0/3，Opus 0/0/3。常驻的那句话
  六次都没管住，拦下级的钩子次次管住。
- D04 本机跑 QE 走 heavy（全机规则）：Haiku 0/0/3（裸 `mpirun` 被拦下后改走 heavy）；Opus 三组都是 2，它自己就走 heavy。
- M06 跑钩子测试别让真 claude 被拉起（注入记忆）：Haiku 1/0/2，Opus 1/0/3。
- C06、C07（注入记忆）：L 组掉下去，N 组补回到 F 的水平。

输的：
- C03 写 EPW 输入的一个参数按项目规矩设（cophon 规则）：Opus 3/0/0。规则只看"写文件"工具，Opus 用 sed 生成文件，规则没响；
  全量组读到了记忆原文。Haiku 1/0/1：规则响了，但它把提醒当成建议、照"其余照旧"没改（FINDINGS 第 6、7 条）。

三组一样的（都守或都不守）：C04 碰集群前读手册三组几乎都是 0：提醒在第一次 ssh 之后才到（FINDINGS 第 4 条），常驻的
全局说明也没管住。D07（某个修正在某种材料上不开）三组都低：注入送到了，模型多半仍照惯例开了修正。对照题（A、N 类）三组全守、
没有误推。

## 局限

- 每格只有 3 次，N 比 F 的提升还不到"可以排除偶然"的程度；结论站得住的是"不降"。
- D04 的假 pw.x 输出和输入对不上（ecut、晶格），Opus 看出来就判"不是真算"不往下做，三组的"活干完"都被压低，组间公平。
- 规则锚在真目录，靠适配层让钩子以为在真目录里（FREEZE_NOTE 第 3 条）；真实使用时不需要。
- 只量了 Haiku、Opus；Fable 未跑。
