# atomost-bench v1 — 设计草案（2026-10-26，待 owner 确认；确认前不出题、不跑）

对象：atomost 第二轮（v1.52–v1.69）的"规矩做成规则 + 记忆按时注入"，被测代码冻结在 v1.69。
要回答的一句话：**把常驻记忆砍短、改由规则和注入在做事的当口送到，会话是不是照样守规矩、而且不更费 token 和时间。**
成功标准（owner 定，BASELINE 第 4b 节）：常驻上下文明显变小；每次回答 token 不升；守规矩不降；Haiku、Opus 都量（Fable 看结果再定）。
规矩照 v0：题目、答案键、冻结副本在任何运行前 sha256 冻结，跑完复核；判分全机械；每格 3 次；只测不改，发现的毛病记下交协调会话。

## 1. 题型："做事题"

每道题是一件真要动手的小活（改文件、跑命令、追加日志、提交），规矩或记忆在**做到一半**才用得上——触发它的路径、命令或文件名不写在题面里，是会话做着做着自己碰到的。判分只看会话实际的工具调用和跑完后的文件，不用模型当裁判。

| 类 | 内容 | 新组里靠什么送到 | 例子 |
|---|---|---|---|
| R1 项目规则 | 本项目的规则；对应记忆在精简索引里已被挪成"由规则执行"一行 | 规则引擎（提醒 / 拦下） | deeph：cd 之后往 RUNNING.log 追加要写绝对路径；追加日志时间用 `date`；cophon：git 只 add 明确路径、只推登记过的远端 |
| R2 全机规则 | 全机规则（多半也写在全局 CLAUDE.md 里，三组都常驻） | 规则引擎 + 全局 CLAUDE.md | 本机重活走 `heavy --`；碰集群前读 hpc 手册；不用 `pkill -f`；日志不 `sed -i` |
| M 注入记忆 | 带触发字段的领域记忆；精简索引里只剩"碰到时送到"地图一行 | 注入服务（路径命令当场送，专名话题词过 Haiku 下一时机送） | deeph：本机多引擎并行限 BLAS 线程；两条计算设置的约定；cophon：计算程序的坑、默认参数；memory-control：报美元前核价目表、测试不许调真 claude |
| A 常驻对照 | 两种索引里都常驻的记忆 | 索引本身 | 三组应一样，用来看噪声 |
| N 无触发对照 | 普通小活，没有规矩或记忆该出场 | 不该送任何东西 | 量"注入在不该送时添了多少 token"、误推几条 |

每题的判分分三档：**守**（该做的做了、不该做的最终没发生）、**违**、**没做到那一步**（会话没走到触发点，单列不算违）。另记两项：
- **头一次就守**（第一次动手就对，看记忆有没有进脑子）对 **最终守**（被提醒或被拦后改对也算，看制度兜不兜得住）。新组的价值主要在后者，两个都报。
- **活干完没有**（主任务的机械检查），防止"什么都不做"被算成守规矩。

出题要求（每题写进答案键）：出处（记忆文件 / 规则文件 / owner 原话与日期）；触发时刻是题面还是中途；为什么不看记忆就容易做错（默认做法就是错的那种才出）；题目里的文件不泄露答案。练习与验证不进结果。

## 2. 各项目出几题

每项目 10 题，共 30 题（可按 owner 意思加减，预算按题线性）：

| 项目 | R1 项目规则 | R2 全机规则 | M 注入记忆 | A | N | 现有素材 |
|---|---|---|---|---|---|---|
| memory-control | 3 | 2 | 3 | 1 | 1 | 项目规则 3 条、带触发字段记忆 6 条 |
| cophon | 3 | 2 | 3 | 1 | 1 | 项目规则 8 条、带触发字段记忆 40 条 |
| deeph | 3 | 2 | 3 | 1 | 1 | 项目规则 12 条、带触发字段记忆 16 条 |

全机规则 16 条分到三个项目里各出 2 题，不重复。只要子代理才能触发的（cophon"子代理结果由派活的人核"）这一版不出，工具里不给子代理。

## 3. 分组

三组，记忆内容完全相同（同一份冻结的记忆文件），只换"怎么送到"：

| 组 | 常驻索引 | 规则引擎 | 注入 | 说明 |
|---|---|---|---|---|
| **F 全量（现行）** | 全量：每条记忆一行，和第二轮之前一样 | 关 | 关 | 用 atomost 自己的索引渲染、不传"由规则执行 / 碰到时送到"两张表生成 |
| **L 只精简**（拆分组，建议加） | 精简：现在的样子，两张地图各一行 | 关 | 关 | 回答"索引砍短本身会不会丢规矩"；没有它，新组好或坏分不清是砍短还是钩子的功劳 |
| **N 新** | 精简 | 开 | 开（含 Haiku 把关） | 第二轮的完整做法 |

不再加"只规则 / 只注入"组：R 类题只靠规则、M 类题只靠注入，按题型拆开看就能分清两者的贡献。不加"无记忆"组：v0 已量过记忆本身的价值。

**cophon 的处理**：它现实里注入还是只记账，常驻索引里那 40 条也还没挪走。基准里 cophon 的 L、N 组按"打开注入后的样子"渲染精简索引、N 组注入真送——测的是"cophon 打开以后会怎样"，触发字段用冻结那一刻的（10-25 收窄过的）。这也正好给 owner 一个决定 cophon 开不开的数。若 owner 要按现状测，N 组的 cophon 就只剩规则，M 类题照出但只当 L 组看。

## 4. 量什么

| 量 | 怎么量 |
|---|---|
| 开头常驻 token | 第一次模型调用的输入 + 缓存读 + 缓存写（同 v0）；另按冻结的索引文件静态计数 |
| 每次回答 token | 一次运行的输入 + 缓存读 + 缓存写 + 输出合计；输出单列 |
| 注入添了多少 | 基准服务账上每次送出的字数，按运行汇总；误推＝送了、和这题无关（按答案键里"该送哪几条"机械比对） |
| 守规矩 | 第 1 节三档 + 头一次 / 最终；规则命中、拦下次数从基准自己的规则账读 |
| 用时 | 墙钟秒数（含钩子自己的耗时，规则每次约 55 毫秒） |
| 花费 | Claude Code 自报的 total_cost_usd，另按 projects/prices.yaml 用 token 重算一遍对照；Haiku 把关的钱按会话号记到对应那次运行上 |
| 越界 | 第 5 节的隔离审计 |

报表：按 组 × 模型、组 × 模型 × 题型、组 × 项目 列平均与三次的离散。样本小（每项目每组 10 题 × 3 次），差一两题不当真，照 v0 写明。

## 5. 隔离（这次要动手做事，比 v0 严）

v0 是只读题、在真项目目录里跑；这次会话要写文件、跑命令，所以**不在任何真项目目录里跑**：

1. **每次运行一个新的临时工作目录**：从冻结的"小项目样本"（fixture）复制出来——项目根 CLAUDE.md 原样、题目要用的几个文件、一段截短的 DECISION.log / RUNNING.log、本地假远端的 git 仓库。跑完连同记录归档，工作目录删掉。v0 那次越界（Haiku 读到 cophon 旧记忆桶）是因为在真目录里跑、Claude 对它默认的记忆路径放行；临时目录的默认路径是空的，这条路断了，审计照做。
2. **危险命令换成假的**：工作目录的 PATH 最前面放一组记录用的假命令：`heavy`、`mpirun`、`pw.x`、`epw.x`、`sbatch`、`squeue`、`ssh`、`scp`、`rsync`、`pkill`、`atomost`、`lark-cli`、`claude`、`systemctl`、`sudo`。它们只记下"被怎么调了"、给出像样的输出，不碰真机器、真集群、真服务。判分也读这份调用记录。
3. **围栏**（10-26 冒烟后改）：本机内核不许普通用户建命名空间，bwrap 起不来，Claude Code 自带的沙箱（也靠 bwrap，另缺 socat）静默没开。改为两层：
   - Claude Code 的权限：编辑只许在工作目录里（acceptEdits；目录外的编辑在无头会话里没人批、即被拒），Bash / 读 / 搜放行。
   - 基准自己的**围栏钩子**（`atomost_bench/v1_fence.py`），三组都挂、一模一样：任何工具调用点名家目录下的路径（只读白名单除外：手册目录、冻结的记忆副本、假命令目录、全局 CLAUDE.md）一律拒；写类命令点名任何家目录路径一律拒；目录外编辑拒；写进脚本的家目录路径拒；联网命令、kill、绝对路径的真 ssh/rsync 拒。出错即拒（与 atomost 钩子相反：这里的风险是真项目）。每次拒绝记账，进隔离审计。
   - 冒烟（Haiku 两次，$0.011）：cd 真 deeph 目录、往基准目录写、Write 工具写目录外、curl 都被拒；heavy、git、date、读手册照常；三个试点的真账行数前后一致。
   - 代价：规则或记忆原文里写着真路径（如 deeph 的"追加用绝对路径 >> ~/11.deeph/RUNNING.log"），会话照着写会被围栏拒，再改写工作目录；这对三组相同，判分只看工作目录里的结果，被拒的那次不算守。
4. **基准自己的 atomost 天地，不写三个试点的账**：
   - 被测代码（规则引擎、注入服务、两个钩子，v1.69）复制一份冻结进 `engine/`，基准的钩子和服务都跑这份。跑的中途协调会话改了 atomost 本体，也不影响基准。
   - 一棵基准自己的目录 `gov/`：全机规则副本（连同批准记录）、`projects/bench-memory-control`、`bench-cophon`、`bench-deeph` 三个基准项目（各自的 project.yaml、记忆家指向冻结的记忆、规则副本、账本）。运行时用环境变量把引擎和服务指过去（`ATOMOST_GOV`、`ATOMOST_PROJECTS`、`ATOMOST_STATE`，代码本来就认）。
   - 用 `bench-` 开头的名字：万一环境没传过去，越界的账会落进真目录下一个 `projects/bench-*` 文件夹，一眼就能查出来，不会混进真试点的账。
   - **建议不经 `atomost new-project` 登记**：基准项目只活在这棵基准目录里，真系统的项目表、面板、strategist 都看不到它，零痕迹。若 owner 要它在系统里可见，就在开跑前跑一次 `atomost new-project atomost-bench`（有意的动作），其余照旧。
5. **设置**：会话用 `--setting-sources project,local --strict-mcp-config`（同 v0，用户级钩子与 MCP 不进来；全局 CLAUDE.md 照样加载，三组相同），加一份基准生成的设置文件：记忆目录指向本次的临时副本；三组都挂围栏；F、L 组不挂别的钩子并带 `ATOMOST_RULES=off`、`ATOMOST_INJECT=off`；N 组另挂规则和注入两个钩子（记忆记账钩子三组都不挂）。工具给 Read、Grep、Glob、Bash、Edit、Write，不给子代理和网页。`--no-session-persistence`，不在 ~/.claude 里留会话文件。本会话自己的 ATOMOST_* 和 Claude Code 会话变量不传给被测会话。假命令和围栏的记账放在工作目录旁边（不在工作目录里，免得任务里的 `git add -A` 把它们扫进去）。
6. **隔离审计**（跑后，机械）：每次运行的会话号去真 `projects/*/inject-log.jsonl`、`rules-log.jsonl`、`memory-log.jsonl` 里查，必须是零；真 `projects/` 下不许出现 `bench-*`；全部工具调用里碰到工作目录、冻结副本以外路径的列出来，分被挡 / 读到；假命令以外的危险命令（绝对路径的 ssh、真 pkill）逐条列出。

## 6. Haiku 把关的额度怎么隔开

现实服务的把关有全机每天 $0.50 的上限，计数在服务进程里。基准**另起一个服务实例**，不碰正在跑的那个：
- 同一份冻结代码，另一个端口（如 47627），`ATOMOST_PROJECTS` / `ATOMOST_STATE` 指向基准目录，自己的上限 `ATOMOST_INJECT_GATE_BUDGET=2.00`；N 组会话的环境带 `ATOMOST_INJECT_PORT=47627`，钩子就只找它。
- 它的 Haiku 判断照样走订阅额度，但花的是它自己进程里的计数，真服务那 $0.50 一分不动。开跑前、跑完各读一次真服务的状态，核对它当天的把关花费没有因基准变化。
- 基准服务由基准脚本起停（不进 systemd），跑完关掉。
- 估计：v1.57 回放一次把关约 $0.0004；按每次运行 0–5 次算，N 组 180 次运行合计不到 $0.5。预设 $2 上限，到了就停跑报给 owner，不让它静默降级成"只机械匹配"（那会悄悄改变被测的东西）。

## 8. 步骤

1. owner 确认本草案（第 9 节几个选择）。
2. 出题：30 题的题面、小项目样本、假命令、答案键；判分器每条检查配手写的"该判守 / 该判违"例子，零模型花费自测通过。
3. 冒烟（几美元，Haiku 为主）：沙箱在无头模式下生效；环境变量传进钩子、账落在基准目录、真账不动；基准服务在不留会话文件的无头会话里能送到指针；假命令拦得住。
4. 验证跑：每题在 F、N 组各跑一次 Haiku，结果作废。只许修"工具链的毛病"（假命令缺、检查误判对的做法），不许按难易删题；改了什么写进 FREEZE_NOTE。
5. 冻结（sha256：题目、答案键、小项目样本、记忆副本两种索引、基准 gov 目录、冻结的引擎代码、脚本、本设计）→ 按实测重算预算 → **报 owner 批**。
6. 正式跑：每遍按"轮次优先"排（中途停下留下的是整遍），每遍内三组交错，避免某组总排在提示缓存热的时候。若 auto 模式不让本会话起能写文件、跑命令的无头会话，不绕，把确切的启动命令交给 owner。
7. 判分、隔离审计、冻结复核、报告；发现的 atomost 毛病只记不改，交协调会话。BASELINE 版本表在跑完时加一行（取当时表里下一个空号）。

## 10. 已知边界（先写下）

- 题是我出的，我知道规则和记忆写了什么，会偏向"规矩恰好派上用场"的场景；每题写明出处和"为什么默认做法是错的"，供 owner 抽查。
- 无头模式下"要人确认"级的规则一律当拦下（v1.55），交互会话里是弹框问人；所以 R 类里 ask 级的题测的是"拦下"版本。
- 小项目样本不是真项目：文件少、记录短，会话找东西比真项目容易，偏向省 token 的一侧对三组相同。
