## 结论

**修的几处在机制上全部生效；成功标准仍守得住，但"守规矩"的提升幅度和 v1 差不多，没有再拉开。**

| | Haiku F | Haiku N | Opus F | Opus N |
|---|---|---|---|---|
| 开头常驻上下文（中位） | 13,977 | 12,275（−12%） | 13,146 | 11,446（−13%） |
| 每次总 token（平均） | 115,608 | 116,507（+1%） | 88,239 | 91,991（+4%） |
| 每次美元（含把关） | 0.0055 | 0.0056 | 0.1410 | 0.1459 |
| 守规矩（冻结的答案键） | 67/89 | 75/90 | 81/90 | 85/89 |
| 守规矩（被拦下的尝试不算违，见下） | 67/89 | 80/90 | 81/90 | 88/89 |
| 活干完（90 次） | 88 | 85 | 83 | 85 |

- **常驻**：和 v1 一样少约 1,700 token（索引没变）。
- **token**：Haiku +1%，Opus +4%。按题配对看（每题 N 对 F 的比值），两个模型都在 +2~3%，偶然性 p≈0.6，量不出差别。
  Opus 多出来的集中在全机规则那类题（+21%）：被"拦一次"拦下后要重来一步。
- **守规矩**：按冻结的答案键，N 比 F 多 8 次（Haiku）、4 次（Opus）；按题配对的偶然性 p≈0.19、0.50。
  同一份 F 组（没有钩子，什么都没改）Opus 从 v1 的 75 变成 v2 的 81：**同样的条件，两天之间就差 6 次**。所以 ±5 次以内的总分
  变化都当不了真，要看逐题的机制。

**冻结的答案键有一处偏差（基准自己的问题，不是 atomost 的）**：C04、D02 的答案键是在 v1 写的，当时规则只会事后提醒，所以把
"拦下的那次尝试"也算成违规。现在规则先拦，会话被拦下、改对再做，按出题说明（"被拒之后做对算守"）该算守，冻结的键却算违。
冻结的分数照报，另列一行"被拦下的尝试不算违"：只改这两题，其余照旧（F 组没有钩子，不受影响；v1 这两题没有被拦的情况，也不受影响）。

## 其他看到的

- deeph 的 D02（cd 之后写日志用绝对路径），Haiku N 按冻结的键从 v1 的 3 掉到 1：三次都是先被"日志不带日期"拦下，那条被拦的命令
  恰好是 `cd 根目录 && … >> RUNNING.log`，第二次改写成绝对路径、加 `$(date)`，最终三次都对。这就是上面答案键偏差的那一题。
- M06（跑钩子测试时 claude 不能在 PATH 上）Haiku 2 次判违：一次是会话想把假命令目录从 PATH 里去掉，被基准的围栏当成"读系统工具"
  拦了（围栏的误拦），只好照原样跑；另一次先带着 PATH 上的 claude 跑了两遍才去干净。
- 对照题（A、N 类）两组都守，没有误推。
