# atomost-bench v0 — 设计（2026-10-17，冻结前）

对象：atomost（`~/4.memory_control`，v1.41）本身，即项目、记忆和会话的治理层；不是哪个项目的研发流水线。
目的：给"atomost 的 AI 能力"拿出能对外讲、经得起查的数字，四个方向是 AI 调度、人机互相赋能、上下文管理、token 节省。owner 2026-10-17 批准预算（标价 50–100 美元）。
规矩（照 cophon 基准）：题目和答案键在任何运行之前冻结（`FREEZE.sha256`）；机械判分，不用模型当裁判；每格 3 次；基准只测不改，发现的 atomost 缺陷写进报告。

## 题 1：新会话接不接得住团队的规矩（上下文管理 + 人机互相赋能）

- 做法：同一个模型，在项目自己的文件夹里无头启动（`claude -p`），只换注入的记忆目录。会话可以用 Read、Grep、Glob 查项目文件夹，读不到外面（无头运行没法授权，10-17 实测被拒）。用户级设置、钩子和 MCP 关掉；全局 `~/.claude/CLAUDE.md` 每组都会加载（实测），是常量。
- 三组记忆（冻结副本在 `arms/`）：
  - none：空目录，等于没有记忆，只能自己翻项目文件。
  - native：atomost 接管之前，Claude Code 自己的分配规则给这个项目的会话的记忆。
    - cophon：根目录自己的桶，55 条，索引 19.4 KB，未整理；从子目录桶写下的 18 条它看不到（`arms/_reference/cophon-jiaming-source/`，只作参考）。
    - deeph：家目录总账本，87 条，混着各项目的规矩。deeph 的会话 10-13 之前一直加载它，原因是 Claude 自己 08-23 建的空 `~/.git`，v1.29 查明并修掉。
    - new-tech-tests：根目录自己的桶，27 条。
  - atomost：项目现在的记忆家（参谋会话整理过）。cophon 55 条、索引 9.6 KB；deeph 8 条；new-tech-tests 19 条。
- 题目：约 44 道情境选择题（A–D，E 固定为"资料里查不到，先问人"）。题目来自 owner 定过或确认过的规矩，且只取冻结日以前的规矩（cophon 10-08、deeph 10-12、new-tech-tests 10-13），因为在那之后的规矩，原生状态下的会话日后也会学到。
  - 题型：两边都有；只在 atomost 里（原生会话看不到的桶）；只在原生里（整理时丢了，如实收录）；串味陷阱（deeph：总账本里别的项目的规矩用在 deeph 是错的）；虚构前提（团队没定过的事，答案是 E）。
  - 出题的子代理读三组记忆和项目文件，逐题给出原文出处，并核对"答案不是最长的选项"。
- 模型：Haiku 5.5、Opus 5.5（与 theory-cache-bench 一致，不用 Fable）。每题、每组、每模型各 3 次。
- 指标：
  - 答对率；
  - 串味次数（选了陷阱项）；
  - 非虚构题选 E 的次数（过度谨慎）；
  - 每次运行的 token、美元（Claude Code 自报的 total_cost_usd）、秒数、工具调用次数；
  - 开场上下文大小（第一次调用的输入 + 缓存读 + 缓存写）；
  - 被拒的越界读取次数（隔离审计）。
- 脚本：`../atomost_bench/t1_bench.py`（prompts / run / grade）；练习题只跑在临时目录，不进结果。

## 题 2：唤醒策略账（AI 调度 + token，不调用模型）

用参谋计时器 10-07 以来的真实检查记录和每轮的真实花费（按 v1.41 的算法），回放五种唤醒策略：
- 现行：按事件唤醒，每天最多一次；
- 每小时一轮；
- 每个有显著变化的小时一轮；
- 每天固定一轮；
- 常驻会话每小时轮询一次。

比较的是轮数、花费，以及从"有变化"到"处理完"的延迟。现行以外的都标"模拟"。旁边并列机器体检、飞书日报的新旧流程。
脚本：`../atomost_bench/t2_wake_policies.py`；结果：`tables/T2.md`。

## 题 3：事故回放（人机互相赋能，不调用模型）

把 09-17 以来所有连续报错和输出截断，喂给控制台现在的识别规则（v1.32 / v1.32.1，`apps/tmux-mobile-control/src/attention.js`、`structured-conversation.js`），量两个时间：
- 规则能报警的时刻；
- 历史上人实际接手的时刻。

两者之间浪费的时间和 token 一并记下。这是"把规则放在历史上回放"，不是观察到的提速。
脚本：`../atomost_bench/t3_incident_replay.py`；结果：`tables/T3.md`。

## 已知的边界（先写下，报告里展开）

- native 组是"冻结在接管那一刻的原生状态"，不是完美的反事实：原生状态下，后来的规矩也会写进原生桶。所以只出冻结日以前的规矩题。
- 项目文件夹本身（DECISION.log、README、records/）里也写着很多规矩。none 组可以去翻，代价是 token 和时间，这正是要量的。
- deeph 的 native 是总账本，这个状态来自一个已修好的事故（空 `~/.git`）。它说明的是"没人治理时会发生什么"，不是 Claude 的常态。
- 题目由知道答案在哪的子代理出，会偏容易；样本小（约 44 题 × 3 次）。差一两道题的比较不要当真。
